### `html`/`body` background — safe-area vs. desktop gutter split

Current code has a single unconditional rule reusing the primary brand color for two unrelated jobs (mobile safe-area gap fill above the header, and desktop letterbox gutter). BRIEF locks two different values for these — `#0a1f6e` for iOS safe-area, `#e8eeff` for the desktop gutter — so the rule must split:

```css
body, html {
  margin: 0;
  padding: 0;
  background: var(--color-primary); /* #0a1f6e — mobile default, matches header, fills safe-area gap */
}

@media (min-width: 431px) {
  body, html {
    background: var(--color-bg-secondary); /* #e8eeff — desktop gutter, once viewport exceeds the 430px app-container */
  }
}
```

`.app-container` keeps `background: var(--color-bg)` (unchanged, per BRIEF).

## 4. Locked invariant — card category color is item-type-driven, not section-driven

`FoodCard.tsx` and `CheckCircle.tsx` key their styles off a `session: "morning" | "evening" | "med"` prop. This prop is **already wired correctly at the call site** — `MorningSection.tsx` and `EveningSection.tsx` both pass `session="med"` for any `Medication` object regardless of whether it renders in the AM or PM list (confirmed: `MorningSection.tsx` morning-meds loop uses `session="med"`; `EveningSection.tsx` evening-meds loop also uses `session="med"`; only actual treatment-food rows get `session="evening"`).

**Rule for this migration:** only change the *token values* inside `FoodCard.tsx` and `CheckCircle.tsx`'s `SESSION_*` lookup objects (morning→navy family, evening→cyan/treatment family, med→amber family). Do **not** touch how `session` is computed or passed at any call site (`MorningSection.tsx`, `EveningSection.tsx`, `FoodItem.tsx`, `FoodGroupRow.tsx`). The category-by-item-type behavior already exists; this phase only recolors it.
